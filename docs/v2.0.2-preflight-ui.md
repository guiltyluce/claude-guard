# v2.0.2 启动前门禁视觉升级

## 目标

`v2.0.2` 让官方 Claude 通道的启动前检查更容易扫读，但不改变 Guard 的安全
判断。视觉层只展示既有检查的进度和结果，不增加探测、不改路由，也不参与
Claude Code 进程生命周期。

## 交互终端呈现

在支持 UTF-8 的交互终端中，预检按以下 8 步呈现：

1. 配置与生命周期
2. 项目与参数边界
3. 客户端身份与指纹
4. 出口 IP 获取
5. Anthropic API TLS
6. Claude 登录 TLS
7. IPv6 泄漏
8. 出口白名单

示例：

```text
Claude Guard · Official Preflight  v2.0.2
  profile  ~/.claude-official
  route    http://127.0.0.1:7897

  ✓  [████████████████] 8/8  出口白名单
       IP 检查通过：203.0.113.10

  ✓  预检已通过  8/8  2s
```

状态含义：

| 状态 | 含义 | 启动行为 |
| --- | --- | --- |
| `✓` | 检查通过 | 继续 |
| `!` | 既有策略允许继续的软警告 | 继续，并在总结果计数 |
| `×` | 既有 fail-closed 条件命中 | 保持原退出码并阻止启动 |

检查中的一行只在真实 TTY 内原地刷新。实现没有 spinner 子进程、计时器 sidecar
或额外 sleep，因此不会改变检查耗时和进程模型。

## 呈现模式

`CLAUDE_GUARD_UI` 支持：

| 值 | 行为 |
| --- | --- |
| `auto` | 默认值。只在 stderr 是交互 TTY 且 `TERM` 不是 `dumb` 时显示视觉预检 |
| `always` | 强制显示，主要用于人工演示和快照测试 |
| `never` | 始终使用旧版纯文字输出 |

设置 `NO_COLOR=1` 会关闭 ANSI 颜色，但保留步骤、图标和进度条。非 UTF-8 locale
会把 Unicode 图标和进度条回退为 ASCII。

以下情况默认不会输出 ANSI 控制序列：

- `claude --precheck-only > report.txt 2>&1`
- CI 或其他非 TTY 调用
- `TERM=dumb`
- `CLAUDE_GUARD_UI=never`

## 安全边界

本版本没有改动：

- `allowed_ips` / `allowed_cidrs` 判定；
- 未授权 IP 的退出码 `4` 和不可绕过语义；
- HTTP CONNECT 代理和 Anthropic 官方 endpoint；
- TLS issuer、中间人、IPv6 泄漏与客户端身份检查；
- official profile、OAuth、settings 和 session 连续性；
- lifecycle fail-closed、blocked plugin 和 CLI 参数策略；
- dry-run guardian 的频率、状态机和日志；
- 任何网络请求的目标、数量、超时或重试次数。

视觉失败摘要由 shell 的 `EXIT` trap 追加，只读取既有退出状态，不拦截或改写
退出码。Guard 仍以原始错误消息作为诊断依据。

## 验证

`tests/preflight_ui.sh` 使用本地 fake `curl`，不访问真实 Anthropic 服务，也不使用
账号凭据或模型额度。它覆盖：

- 8 步成功视觉输出；
- 平台 TLS 软警告；
- 未授权 IP fail-closed 与退出码 `4`；
- `auto` 在非 TTY 中回退纯文字；
- `never` 保留纯文字输出；
- `NO_COLOR` 不包含 ANSI escape；
- 失败输出不会误报“预检已通过”。

完整验证命令：

```bash
./scripts/check.sh
shellcheck bin/claude-guard tests/preflight_ui.sh scripts/check.sh
```

## 使用影响

日常执行 `claude` 或 `claude-official` 时，会先看到一段更紧凑的进度界面。检查
项目、网络请求、确认提示和最终启动的 Claude Code 都与 `v2.0.1` 相同。依赖旧版
文字输出的自动化无需修改，因为默认 `auto` 在非 TTY 中会自动回退。
