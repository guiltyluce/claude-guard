# v2.0.3 Watchdog 观测加固

## 背景

长期运行日志显示，旧版 dry-run watchdog 在进入逻辑 paused 状态后，会因为每个
5 秒 tick 都重新检查 API 而放大探测和日志。多个前台 Claude 会话各自运行 sidecar
时，这种放大会进一步叠加。日志还无法为普通 warning 标注所属 Claude PID，并把
IP 查询源失败统一写成 `unknown`，不利于区分“没有观测结果”和“观测到错误出口”。

`v2.0.3` 只修正这些观测问题。它不实现进程 pause，不修改 Claude 请求，也不改变
账号、OAuth、profile、session 或网络路由。

## 新的探测节奏

正常状态保持原频率：

- 出口 IP：每 60 秒；
- Anthropic API CONNECT/TLS：每 180 秒；
- watchdog tick：每 5 秒，仅用于状态机和 sleep/wake 检测。

达到 IP 或 API 失败阈值后，watchdog 仍然只记录 `would pause`，随后进入逻辑
paused 状态。paused / resume-pending 状态不再每个 tick 探测 API，而是默认每
30 秒执行一轮成对检查：

1. 获取出口 IPv4；
2. 确认该 IP 在 allowlist；
3. 验证 `api.anthropic.com` 的 HTTP CONNECT、TLS 和 issuer；
4. 只有同一轮 IP 与 API 都健康，才增加一次恢复计数。

连续两轮成对检查通过后记录 `would resume`。每轮之间的 30 秒从上一轮探测完成后
开始计算，因此网络超时本身不会把下一轮探测挤成无间隔重试。

可通过以下变量调整恢复间隔：

```bash
CLAUDE_GUARD_RECOVERY_INTERVAL=30
```

## 日志语义

所有 watchdog runtime 事件都带 `pid=<target Claude PID>`。多会话仍各自运行
watchdog，但共享日志中的事件可以按 PID 归因。

IP 事件分为：

- `exit ip unavailable`：所有 IP 查询源均未返回有效 IPv4；
- `exit ip not allowed ip=...`：成功取得 IPv4，但它不在 allowlist；
- `route healthy ip=...`：降级状态恢复。

正常失败计数最多记录到阈值。进入 paused 后，如果恢复探测持续失败，只记录首次
和每第 10 次；恢复候选和最终 `would resume` 仍完整记录。

sidecar 在以下退出路径写入原因：

- `reason=target-gone`
- `reason=signal-HUP`
- `reason=signal-INT`
- `reason=signal-TERM`

`SIGKILL` 无法被进程捕获，因此仍不可能留下退出日志。

## 日志轮转

默认当 `guard.log` 大于 1MB 时，将其移动为 `guard.log.1`，只保留一份归档：

```bash
CLAUDE_GUARD_LOG_MAX_BYTES=1048576
```

多个 watchdog 会通过同目录的短生命周期 lock 协调轮转。设置为 `0` 可关闭轮转。
日志仍然不记录 token、prompt、response 或会话正文。

## 多会话边界

本版本没有把多个 sidecar 合并成全局 singleton。每个前台 Claude 会话仍有自己的
watchdog，因此正常探测数量与会话数成正比。这样保留了明确的父子生命周期，也
避免在本版本引入 IPC、共享锁租约和 singleton 崩溃后的接管问题。

## 安全边界

本版本保持：

- `CLAUDE_GUARD_WATCHDOG_DRY_RUN=1`；
- action mode 继续拒绝启动；
- 不发送 `SIGSTOP`、`SIGCONT`、`SIGTERM` 或 kill；
- 不修改 Anthropic endpoint、TLS、请求正文或凭据；
- 不改变 IP/API 阈值；
- 不改变启动前 fail-closed 和退出码；
- 不影响 `claude-cc` 或 CC Switch 通道。

已经运行的旧 sidecar 不会热更新。安装 `v2.0.3` 后，新行为只对下一次启动的
Claude 会话生效。

## 验证

`tests/watchdog_runtime.sh` 使用真实 launcher、fake Claude 和 fake curl，覆盖：

- IP 查询长期不可用时，API 恢复探测不会按 tick 放大；
- IP unavailable 与 not allowed 分开记录；
- 失败阈值、would-pause、成对恢复与 would-resume；
- 所有 runtime 日志包含目标 PID；
- target-gone 退出记录；
- 超限日志轮转。

fixture 使用文档保留地址，不访问互联网，不读取真实配置，也不使用账号或模型额度。

完整验证：

```bash
./scripts/check.sh
/bin/bash ./scripts/check.sh
shellcheck bin/claude-guard tests/watchdog_runtime.sh tests/lifecycle_policy.sh
```
